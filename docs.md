# Документация проекта ActiveSec

## Обзор

ActiveSec - это комплексное решение для анализа и защиты систем безопасности. Проект состоит из трех основных компонентов: AS-NET (машинное обучение), Client (клиентская часть) и Driver (драйвер безопасности), которые работают совместно для обеспечения безопасности и мониторинга системы.

## Архитектура проекта

### AS-NET (Машинное обучение)

Компонент AS-NET содержит модели машинного обучения, разработанные с использованием PyTorch. Основной компонент - это CNN-модель для анализа последовательных бинарных данных.

#### Модель main_model

Модель `SequentialBinaryCNN` предназначена для обработки последовательных бинарных данных с использованием эмбеддингов. Основные особенности:

- **Эмбеддинги**: Преобразует бинарные значения (0-255) в плотные векторные представления
- **1D свертки**: Обработка последовательных данных с помощью одномерных сверточных слоев
- **Инициализация в цикле**: Слои инициализируются в цикле для гибкой настройки архитектуры
- **GeLU активация**: Используется современная функция активации GeLU для лучшей производительности
- **Гибкая архитектура**: Возможность настройки количества каналов, размеров ядра и других параметров

##### Параметры модели:
- `vocab_size`: Размер словаря (по умолчанию 256 для байтовых значений)
- `embedding_dim`: Размерность эмбеддинга
- `sequence_length`: Длина входной последовательности
- `num_classes`: Количество классов для классификации
- `conv_channels`: Список количества каналов для сверточных слоев
- `kernel_sizes`: Размеры ядер для сверточных слоев

#### Обучение моделей

Директория `train` содержит скрипты и конфигурации для обучения моделей. Процесс обучения включает:

1. Подготовку данных
2. Настройку гиперпараметров
3. Запуск процесса обучения
4. Оценку качества модели

### Client (Клиент)

Клиентская часть приложения, обеспечивающая взаимодействие с пользователем и интерфейс управления системой безопасности.

#### Структура клиента

- **Core**: Основные классы и логика приложения
- **IO**: Модули ввода-вывода и обработки данных
- **Native**: Взаимодействие с нативными библиотеками и API
- **Security**: Модули безопасности и криптографии

#### Основные функции клиента:

- Взаимодействие с пользователем через интерфейс
- Сбор и отправка данных для анализа
- Прием результатов анализа от моделей машинного обучения
- Управление настройками безопасности
- Взаимодействие с драйвером безопасности

#### Архитектура

Клиентская часть написана на C# и использует .NET Framework/.NET Core. Она обеспечивает:

- Многопоточную обработку данных
- Безопасное хранение конфиденциальной информации
- Интеграцию с системными API Windows
- Связь с драйвером через механизмы IPC

### Driver (Драйвер безопасности)

Низкоуровневый компонент, работающий на уровне ядра операционной системы, обеспечивающий мониторинг и перехват системных вызовов и других критических операций.

#### Основные функции драйвера:

- Мониторинг системных вызовов
- Перехват файловых операций
- Контроль сетевой активности
- Защита критических процессов
- Сбор телеметрии для анализа

#### Структура драйвера

- **Callbacks.c/h**: Системные коллбэки и обработчики событий
- **Communication.c**: Механизмы связи с пользовательским режимом
- **ActiveSec.inf**: Инсталляционный файл драйвера

#### Архитектура

Драйвер написан на C и использует Windows Driver Kit (WDK). Он реализует:

- Регистрацию системных коллбэков
- Обработку IRP (I/O Request Packets)
- Безопасную передачу данных в пользовательский режим
- Защиту от несанкционированного доступа

## Взаимодействие компонентов

### Клиент ↔ Драйвер

Клиентская часть взаимодействует с драйвером через механизмы IPC (Inter-Process Communication), используя:

- Named pipes
- Device I/O control
- Shared memory

### Клиент ↔ AS-NET

Клиент отправляет данные, собранные драйвером, в модели машинного обучения:

- Предварительная обработка данных
- Форматирование для моделей
- Анализ результатов
- Принятие решений на основе предсказаний

### Драйвер → Клиент → AS-NET

Полный цикл обработки:

1. Драйвер собирает системные события
2. Клиент получает данные от драйвера
3. Клиент отправляет данные в модели AS-NET
4. Модели анализируют данные и возвращают результаты
5. Клиент принимает решения на основе анализа
6. При необходимости клиент взаимодействует с драйвером для блокировки угроз

## Установка и настройка

### Требования

#### AS-NET:
- Python 3.7+
- PyTorch
- CUDA (опционально, для ускорения на GPU)

#### Client:
- .NET Framework 4.7.2 или .NET Core 3.1+
- Windows 10/11 (предпочтительно)

#### Driver:
- Windows Driver Kit (WDK)
- Подписанный сертификат для драйвера (для Windows 10/11)

### Установка зависимостей

#### Для AS-NET:
```bash
pip install torch torchvision torchaudio
# Дополнительные зависимости при необходимости
```

#### Для Client:
Зависимости указаны в файле Client.csproj

#### Для Driver:
Установка WDK из Microsoft

## Использование

### AS-NET

#### Создание и запуск модели

```python
from AS-NET.models.main_model import create_model

# Создание модели с параметрами по умолчанию
model = create_model()

# Или с кастомными параметрами
model = create_model(
    vocab_size=256,
    embedding_dim=64,
    sequence_length=1024,
    num_classes=2
)

# Пример входных данных (батч последовательностей байтов)
import torch
batch_size = 4
sequence_length = 1024
input_data = torch.randint(0, 256, (batch_size, sequence_length))

# Получение предсказания
output = model(input_data)
```

### Client

Клиентская часть запускается как консольное приложение или Windows-сервис. Основные функции:

- Запуск и останов драйвера
- Мониторинг системных событий
- Обработка данных с помощью моделей ML
- Логирование и отчетность

### Driver

Драйвер устанавливается как системный сервис и запускается с правами SYSTEM. Для установки:

1. Подписать драйвер сертификатом
2. Установить через inf-файл
3. Запустить через системный сервис
